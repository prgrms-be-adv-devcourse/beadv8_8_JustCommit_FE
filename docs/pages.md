# 페이지 명세

세미 프로젝트에서 만들 페이지 전체 목록이다. 여기 없는 페이지와 기능(위치 기반 거래, 커뮤니티, 찜, 댓글, 랭킹, 시세, 1:1 상담 등)은 만들지 않는다.

- 권한: `공개` 누구나 / `로그인` 로그인 회원 / `판매자` Role이 `SELLER`인 회원
- API 이름은 [api.md](api.md)의 엔드포인트다. 미구현 API는 목 데이터로 만든다.
- 모든 목록 화면은 로딩, 빈 목록, 에러 세 상태를 함께 만든다.

## 공통 레이아웃 (헤더)

- 왼쪽: 로고(`/`), 검색창
- 오른쪽(비로그인): 로그인, 회원가입
- 오른쪽(로그인): 예치금 잔액 + 충전 버튼(`/wallet/charge`), 장바구니 아이콘(`/cart`), 알림 종 + 안 읽은 수 배지(`/notifications`), 프로필 메뉴(`/mypage`, 로그아웃), "식물 판매하기" 버튼(판매자면 `/seller/products/new`, 아니면 `/seller/register`)
- 푸터: 서비스명과 저작권 한 줄, 이용약관·개인정보처리방침 링크만

## 1. 메인 `/`

- API: 상품 검색, 품종 목록(필터 칩)
- 필터: 품종 칩, 가격 범위, 정렬(최신순·낮은 가격순·높은 가격순), "판매 중만" 토글. 필터 값은 URL 쿼리에 둔다(새로고침·뒤로가기 유지).
- 상품 카드: 대표 사진, 상품명, 가격, 등록 시간, 상태 배지. 판매완료는 흐리게.
- 페이지네이션: "더 불러오기" 버튼
- 상단 히어로: 정책 3가지만 — 예치금 안전결제, 구매 확정 후 정산, 배송 완료 후 자동 구매 확정

## 2. 상품 상세 `/products/:productId`

- API: 상품 상세, 장바구니 담기
- 사진 갤러리, 품종, 상품명, 가격, 상태 배지, 판매자 닉네임, 설명, 등록일
- 버튼: "장바구니 담기", "바로 구매"(장바구니에 담은 뒤 그 항목 하나로 `/checkout?items=<cartItemId>` 이동 — 바로구매 API가 생기면 교체). 판매중이 아니면 둘 다 비활성.
- 에스크로 안내 박스: "예치금으로 결제하고, 구매 확정 후 판매자에게 정산돼요"
- 본인 상품이면 구매 버튼 대신 "수정", "숨기기", "삭제"

## 3. 로그인 `/login`

- API: 로그인. 성공하면 `setAccessToken` 후 `redirect` 쿼리 경로 또는 `/`로 이동.
- 카카오·네이버 버튼은 `/oauth2/authorization/kakao`, `/oauth2/authorization/naver`로 페이지 이동(axios 아님, `window.location`).
- 실패 메시지는 입력창 아래에 표시

## 4. 회원가입 `/signup`

- API: 인증번호 발송, 인증번호 확인, 닉네임 중복 확인, 회원가입
- 1단계 이메일 → 인증번호 받기 → 6자리 입력. 남은 시간 카운트다운(응답의 만료 시간), 재발송은 쿨다운이 끝난 뒤 활성.
- 2단계 닉네임(중복 확인 필수), 비밀번호, 비밀번호 확인
- 3단계 완료 → 로그인으로

## 5. 소셜 가입 추가 정보 `/signup/social`

- API: 소셜 회원가입 완료
- 소셜 로그인에서 처음 온 사용자. 소셜 이메일은 읽기 전용, 닉네임 입력 + 중복 확인.
- 백엔드가 이 페이지로 리다이렉트하는 방식(가입용 토큰 전달 방법)은 확정 전. 백엔드 담당에게 확인하고 [api.md](api.md)에 적은 뒤 구현한다.

## 6. 장바구니 `/cart`

- API: 장바구니 조회, 담기, 삭제
- 수량 선택 없음(1개체 1판매). `isPurchasable`이 false인 항목은 흐리게 + 선택 불가. `isChangedPrice`가 true면 "가격이 바뀌었어요" + 현재 가격(`nowPrice`) 표시.
- 체크박스 선택 → 합계(상품 + 배송비) → "선택 상품 주문하기" → `/checkout?items=<cartItemId,...>`로 이동. 이 단계에서는 API를 호출하지 않는다.

## 7. 주문서 `/checkout?items=<cartItemId,...>` (+ 주문 실패 `/checkout/fail`)

- API: 장바구니 조회(선택 항목 표시), 배송지 목록, 예치금 잔액, 주문 생성(결제하기)
- 화면을 여는 시점에는 주문이 없다. 장바구니에서 고른 항목과 배송지를 보여 주기만 한다.
- 배송지(기본 배송지 + 변경), 판매자별로 묶은 상품, 상품 금액·배송비(판매자별)·총액
- 결제 수단은 예치금 하나: 보유 예치금 → 결제 후 잔액
- 잔액이 총액보다 적으면 안내 + "충전하기"(`/wallet/charge`), "결제하기" 비활성. 잔액 부족 상태로는 결제 요청을 보내지 않는다(서버는 잔액이 부족해도 주문을 결제 대기로 만들고 상품을 10분간 잡아 두기 때문).
- "결제하기" = 주문 생성 API 한 번. 서버가 주문 저장, 상품 예약(락), 예치금 결제를 한 번에 한다. 중복 클릭을 막는다(요청 중 버튼 비활성).
- 응답의 주문 상태가 `PAID` → `/orders/:orderId/complete`
- 응답이 `PAYMENT_PENDING`이면(버튼을 누르는 사이 잔액이 줄어든 경우) "잔액이 부족해 결제하지 못했어요" 안내 후 충전으로 보낸다. 충전 후 결제는 결제 대기 주문 결제 API로 한다.
- 409 `PRODUCT_UNAVAILABLE`, `PRICE_CHANGED`: 실패하면 서버가 모두 되돌려서 장바구니가 그대로 남는다. 장바구니를 다시 조회해 선택했던 항목 중 `isPurchasable`이 false이거나 `isChangedPrice`가 true인 것을 모아 `/checkout/fail`에 보여 준다. 에러 응답에는 상품 정보가 없다.
- `/checkout/fail`: 경고 아이콘, "주문하지 못했어요", 구매할 수 없는 상품 목록(배지 "구매 불가" 하나 — 결제 대기와 판매완료를 응답으로 구분할 수 없음), 가격이 바뀐 상품 목록, "예치금은 빠져나가지 않았어요", 버튼 "다른 식물 보러 가기" / "장바구니로 돌아가기"

## 8. 주문 완료 `/orders/:orderId/complete`

- 주문 번호, 결제 금액, "판매자가 발송하면 알림으로 알려 드려요"
- 버튼: "주문 상세 보기", "쇼핑 계속하기"

## 9. 주문 목록 `/orders`

- API: 구매자 주문 목록
- 카드: 주문일, 주문 번호, 대표 상품 + "외 N건", 결제 금액, 주문 상태
- 상태 탭은 [domain.md](domain.md)의 주문 상태 기준

## 10. 주문 상세 `/orders/:orderId`

- API: 구매자 주문 상세, 구매 확정(취소는 미구현)
- 판매자별로 묶은 상품. 상품마다 주문 상품 상태 배지 + 배송 단계(택배 예약 → 접수 완료 → 배송 중 → 배송 완료) + 송장번호
- 버튼 조건은 [domain.md](domain.md)의 "버튼 활성 조건"
- 안내: "배송 완료 후 일정 기간이 지나면 자동으로 구매 확정돼요"

## 11. 예치금 `/wallet`

- API: 잔액 조회, 거래 내역
- 잔액 + "충전하기", 거래 내역(날짜, 종류, +/− 금액). 종류 표시 이름은 [domain.md](domain.md)

## 12. 충전 `/wallet/charge`

- API: 충전 요청, 충전 승인
- 금액 입력 + 빠른 선택(1만/5만/10만) → 충전 요청 → 토스페이먼츠 결제창
- 결제 후 토스가 `/wallet/charge/success`(또는 `/fail`)로 돌려보낸다. success 페이지에서 쿼리 값으로 충전 승인 API를 호출하고 결과를 보여 준다.
- 토스 클라이언트 키는 공개 키라 `.env`에 둬도 된다(`VITE_TOSS_CLIENT_KEY`). 시크릿 키는 백엔드에만 있다. SDK 도입은 사용자 승인 후.

## 13. 충전 내역 `/wallet/charges`

- API: 충전 내역 조회(미구현), 충전 취소(미구현)
- 요청일, 금액, 상태. 대기 건에는 "취소"

## 14. 마이페이지 `/mypage`

- API: 내 정보, 예치금 잔액
- 프로필, 잔액 카드, 메뉴(주문 내역, 예치금, 배송지, 알림). 판매자면 판매 메뉴(내 판매 목록, 판매 주문, 정산), 아니면 "판매자 등록하기" 배너. 로그아웃.

## 15. 배송지 관리 `/mypage/addresses`

- API: 배송지 목록, 등록, 기본 배송지 설정
- 카드(받는 사람, 연락처, 주소, 기본 배지) + "기본으로 설정". 추가 모달(받는 사람, 연락처, 우편번호 검색, 상세 주소). 우편번호 검색 라이브러리는 사용자 승인 후.

## 16. 알림 목록 `/notifications`

- API: 알림 목록, 안 읽은 수, 읽음 처리, 모두 읽음 (모두 미구현)
- 종류 아이콘(주문·배송·정산), 메시지, 시간. 안 읽은 알림 강조. 누르면 읽음 처리 후 관련 페이지로.

## 17. 판매자 등록 `/seller/register`

- API: 판매자 등록. 성공하면 Role이 바뀌므로 토큰 재발급(`reissueAccessToken`) 후 `/seller/products/new`로.
- 입력: 정산 계좌(은행, 계좌번호, 예금주), 판매 정책 동의

## 18. 상품 등록·수정 `/seller/products/new`, `/seller/products/:productId/edit`

- API: 상품 등록, 상품 수정, 상품 상세(수정 시), 품종 목록, 이미지 업로드(미구현)
- 사진 여러 장(첫 장 대표), 품종 선택(검색 드롭다운), 상품명, 가격, 설명
- 안내: "식물 1개체당 판매글 1개만 등록돼요"

## 19. 내 판매 목록 `/seller/products`

- API: 내 판매 목록, 숨김 변경, 삭제
- 카드 + 상태(판매중 / 결제 대기 / 판매완료 / 숨김). 결제 대기·판매완료는 수정·삭제 비활성.

## 20. 판매자 주문 `/seller/orders`, `/seller/orders/:sellerOrderId`

- API: 판매자 주문 목록, 판매자 주문 상세
- 상세: 구매자 배송지, 상품, 송장번호, 배송 단계, 정산 예정 상태
- 판매자가 송장을 입력하지 않는다. 결제 완료 시 택배가 자동 접수된다.

## 21. 정산 `/settlements`

- API: 정산 요약, 정산 내역, 정산 상세 (모두 미구현)
- 요약 카드(정산 예정, 이번 달 완료, 누적), 내역(날짜, 상품, 판매 금액, 수수료, 정산 금액, 상태)
- 수수료율은 미정. 수수료 칸은 API 값을 그대로 보여 주고, 화면에서 계산하지 않는다.
